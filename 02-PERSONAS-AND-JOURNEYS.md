# People and journeys

## Personas
| Person | Need | Constraint | Design response |
| --- | --- | --- | --- |
| Casual worker | Paid nearby tasks | No CV; limited data | Skills chips; visible pay; town selection |
| Skilled provider | Consistent clients | Small phone; busy hands | Short quote and availability forms |
| Broker/introducer | Fair commission | Attribution disputes | Accepted terms and lead timeline |
| Household customer | Help at a stated time | Limited hiring experience | Guided post and quote comparison |
| Seller/business | Customers and staff | Already uses phone/WhatsApp | Simple listings and optional sharing |
| Moderator | Resolve cases fairly | Conflicting accounts | Evidence timeline and reasoned decisions |

## Journeys
### Worker
Browse without login → select town and Work → inspect pay, hours and requirements → sign in → send availability and short message → accept written offer → do work → request completion → review agreed payment status.
No response is shown as Pending, never as accepted. Changed pay requires fresh acceptance.

### Service provider
Choose skill → publish service and area → receive request → quote with scope, materials and travel costs → customer accepts → perform service → both confirm outcome → record payment → eligible review.

### Seller and broker
Seller drafts listing → enables brokerage → specifies terms → eligible broker accepts → seller authorises broker → broker shares listing or registers consented lead → seller accepts or contests attribution → sale/booking completes → commission claim → seller confirms payment → broker acknowledges receipt.

### Property enquiry (after gate)
Seller/agent supplies authority evidence → listing reviewed → broker accepts terms → consented enquiry → viewing → parties obtain professional checks → qualifying transaction documented → commission outcome. A platform badge never represents title verification.

## Failure journeys
Unavailable listing: explain and offer related search. Expired offer: keep history and allow a new quote. No connectivity: retain draft and show Not sent. Duplicate referral: explain prior claim and allow evidence appeal. Failed payment: show provider result without claiming completion.

## Guest journey (12 Oct 2026)
Visitor lands on Explore-first home → browses Work/Services/Deals with manual town filter → opens listing detail (pay, terms, public seller, reviews) → selects Apply → sees "Create an account to apply" sheet → continues with phone → returns to the same listing with draft preserved, revalidated, and nothing auto-submitted. Closing the sheet never blocks browsing.
